| D55 | 2026-11-25 | **An optional speed-up relay: the relay is only the first address Pipe dials, and one relay serves many servers (0.7.0).** A relay is any Linux box that forwards ports to servers in the kernel (nftables DNAT and masquerade in its own `inet pipe_relay` table; no Pipe process at runtime, no logs, no keys). Each server is a route with its own relay ports: `pipe relay add` (fed by `pipe server relay-command`, IPs and ports only) picks the server's own ports when free, else free ones that no other route and no local listener uses, keeps them on re-add, and prints a **relay code** `<host>[:<tcp>][/<udp-or-range>]` plus the ports to open. `remove [--to]`, `status` and `apply` (the boot unit) manage the routes from one owned state file in one nft transaction. The code is a per-profile app setting with an on/off switch, not part of the link. For a relayed tier, Pipe races the relay against the server: direct starts after 1 s or at once when the relay fails, and only a verified REALITY handshake (Stealth) or Hysteria2 login (Fast) wins, so a wrong or hostile code fails closed. A failed or slow relay is skipped for 60 s; a network change clears that. Failover probes get 1 s more while a relay is set.
